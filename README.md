# Лабораторная работа № 2. Параллельное умножение матриц

## 1. Цель работы

Разработать программу на C++ для умножения двух квадратных матриц, реализовать последовательный и параллельный алгоритмы, проверить корректность вычислений и исследовать зависимость времени выполнения от размера матриц и количества потоков.

## 2. Постановка задачи

Необходимо разработать программу, которая выполняет следующие действия:

1. Считывает две квадратные матрицы из файлов `A.txt` и `B.txt`.
2. Вычисляет произведение матриц последовательным алгоритмом.
3. Вычисляет произведение матриц параллельным алгоритмом с использованием OpenMP.
4. Измеряет время выполнения вычислений.
5. Сравнивает результаты последовательного и параллельного вычислений.
6. Записывает результирующую матрицу в файл `C.txt`.
7. Исследует производительность программы при различных размерах матриц и количестве потоков.
8. Проверяет корректность результата с помощью Python и библиотеки NumPy.

## 5. Алгоритм умножения матриц

Пусть заданы две квадратные матрицы \(A\) и \(B\) размерности \(n \times n\). Результатом умножения является матрица \(C\), элементы которой вычисляются по формуле:

\[
C*{ij}=\sum*{k=0}^{n-1} A*{ik}B*{kj}
\]

Для вычисления каждого элемента результирующей матрицы необходимо умножить элементы соответствующей строки матрицы \(A\) на элементы соответствующего столбца матрицы \(B\), а затем сложить полученные произведения.

В программе реализованы два варианта алгоритма.

### 5.1. Последовательный алгоритм

В последовательном варианте вычисление элементов результирующей матрицы выполняется последовательно с использованием трёх вложенных циклов.

### 5.2. Параллельный алгоритм

В параллельном варианте используется OpenMP. Директива `#pragma omp parallel for schedule(static)` распределяет итерации внешнего цикла между потоками.

Каждый поток вычисляет отдельные строки результирующей матрицы. Поскольку потоки записывают результаты в разные элементы матрицы, одновременное выполнение этих вычислений не приводит к конфликтам при записи.

Трудоёмкость классического алгоритма умножения квадратных матриц составляет \(O(n^3)\).

## 6. Методика эксперимента

Для исследования производительности измерялось время последовательного и параллельного умножения матриц разных размеров.

В эксперименте использовались следующие размеры матриц:

- 200 × 200;
- 400 × 400;
- 800 × 800;
- 1200 × 1200;
- 1600 × 1600.

Исследовалось выполнение параллельного алгоритма с количеством потоков 1, 2, 4 и 8.

Для каждой комбинации размера матрицы и количества потоков выполнялись три повторных запуска. В таблицах представлены средние значения времени выполнения, полученные скриптом `plot.py`.

Ускорение вычислений определяется по формуле:

\[
S=\frac{T*{\text{посл}}}{T*{\text{пар}}}
\]

где:

- \(S\) — коэффициент ускорения;
- \(T\_{\text{посл}}\) — время последовательного выполнения;
- \(T\_{\text{пар}}\) — время параллельного выполнения.

Чем больше значение коэффициента ускорения, тем эффективнее параллельный алгоритм относительно последовательного.

## 9. Анализ результатов

Результаты экспериментов показывают, что параллельное выполнение позволяет сократить время умножения матриц.

Для матрицы размером 1600 × 1600 последовательный алгоритм выполнил вычисления за 23829,486 мс, а параллельный алгоритм с восемью потоками — за 5572,185 мс.

Наибольшее ускорение среди приведённых результатов наблюдается для матрицы размером 1200 × 1200 при использовании восьми потоков:

\[
S=\frac{10068{,}882}{2078{,}603}\approx 4{,}844
\]

Следовательно, в данном эксперименте параллельный алгоритм выполнил вычисления приблизительно в 4,84 раза быстрее последовательного.

При этом увеличение количества потоков не гарантирует пропорционального ускорения. Например, для матрицы размером 400 × 400 использование восьми потоков оказалось немного медленнее использования четырёх потоков. Это может быть связано с накладными расходами параллелизации и особенностями распределения вычислительных ресурсов.

При использовании одного потока параллельный вариант также может работать немного медленнее последовательного из-за дополнительных расходов на организацию параллельной области OpenMP.

Таким образом, эффективность параллельных вычислений зависит от размера задачи и количества потоков.
